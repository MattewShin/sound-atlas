# 홈 탐색 카드

`피아노 음악 만나기`는 감정·기분을 선택하지 않았고 취향 추천도 사용하지 않는 최초 탐색 상태에서 표시됩니다. 이전에는 쇼팽 4곡을 고정 표시했습니다. 이제 기존 `getRecommendationResult(tracks)`가 허용하는 감정 평가 완료 곡 전체에서 4곡을 고릅니다. 선택 조건이 없는 후보는 추천 적합도상 동등하므로 낮은 적합도의 곡을 억지로 섞는 일이 없습니다. 감정·기분·취향을 선택하면 기존 대표곡과 상위 추천 목록으로 전환하며, 기존 점수·순위·미평가 제외·보관곡 제외 기준을 유지합니다. 현재 에너지 선택은 없습니다.

## 교체 시점

- 앱 최초 진입과 새로고침.
- 보관함·공연·취향·소개 글·지난 선정곡·전체 추천 목록 등 다른 앱 화면에서 홈으로 돌아올 때.
- 홈 초기 탐색 상태에서 `isLoggedIn`이 `false`에서 `true`가 될 때.
- 느낌/기분 탭·선택·추천 모드 변경 후 초기 탐색 상태로 돌아올 때.

이미 홈에서 음악 탐색 메뉴를 다시 누르거나, 일반 리렌더링·보관/해제·가로 스크롤·영상 재생·곡 상세/영상 모달 닫기에는 교체하지 않습니다. 로그인과 홈 진입이 같은 업데이트에 발생하면 한 번만 구성합니다. 다른 화면에서 로그인한 경우 홈에 돌아올 때 한 번 구성합니다. 새 구성의 캐러셀은 시작점에서 표시합니다.

현재 프로젝트에는 인증 기능이 없습니다. 인증 연동 시 `src/App.jsx`의 `App`에 실제 인증 상태를 `isLoggedIn` prop으로 전달하세요. 이 연결 지점의 로그아웃→로그인 전환과 홈 진입 동시 처리는 React DOM 테스트로 검증합니다. 가상의 로그인 상태를 저장소에 생성하거나 토큰을 읽지 않습니다.

## 선정과 상태

`src/data/homeDiscovery.js`가 곡 ID를 중복 제거하고, 가능한 경우 직전 작곡가와 다른 작곡가를 고릅니다. 직전 목록에 없는 곡과 아직 등장하지 않은 작곡가를 우선하고 해당 후보 중 무작위로 선택합니다. 후보가 적거나 작곡가가 한 명이면 조건을 완화해 가능한 곡 수만큼 제공합니다. 원본 곡이나 추천 배열은 변경하지 않습니다.

`src/components/useHomeDiscovery.js`가 확정한 목록을 React 상태로 유지합니다. 직전 4곡의 ID만 탭의 `sessionStorage`에 저장해 새로고침에도 반복을 줄입니다. 저장소가 차단되거나 값이 잘못되면 현재 화면의 상태만 사용합니다. 섹션은 노출 중인 `EDITOR’S PICK` 글과 독립적입니다.

주간 소개는 기존 `section-heading` 스타일로 영문 라벨과 한국어 제목을 카드 밖에 표시합니다. 구분선 아래 제목, 제목 아래 18px 여백, 기존 가로형 카드와 선정자/지난 글 링크의 순서입니다. 글이 비노출 상태이면 제목을 포함한 섹션 전체가 숨겨집니다.

검증은 기존 `npm test`에 통합되어 있으며 전체 테스트 114개와 `npm run build`가 통과했습니다. StrictMode 최초 렌더링·홈 재진입·새로고침·로그인 상태 전환·홈 진입과 로그인 동시 발생·스크롤 초기화·보관/해제·영상과 상세 모달·추천 조건 전환을 검증합니다. 모바일·데스크톱 실제 시각 확인은 앞서 정한 대로 사용자가 직접 확인합니다.
