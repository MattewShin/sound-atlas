# KOPIS 기준의 정확한 곡별 공연 검색 v1.0

사용자가 기존 곡 ID 하나와 지역·관람 기간을 선택하면 KOPIS의 클래식 예정·진행 공연을 조회합니다. 해당 공연에 연결된 실제 연주 프로그램에서 선택 작품을 확인한 공연만 **확인된 공연**에 표시합니다. 자료나 작품 식별이 불명확하면 추가 확인 상태로 남깁니다. 결과가 없다는 이유로 해당 작품의 공연이 국내에 없다고 판단하지 않습니다.

## 작업 시작 상태와 범위

- 작업 시작 브랜치는 `main`이며 작업 트리는 깨끗했습니다. `origin/experiment/sac-calendar-probe`는 그대로 보존했고 병합하지 않았습니다.
- 기관별 API·크롤링·유료 OCR·여러 곡 동시 검색·감정 기반 공연 검색·예매는 추가하지 않았습니다. 예술의전당과 롯데콘서트홀도 KOPIS 공연 ID와 상세·소개 자료로만 처리합니다.
- 현재 `src/data/concerts.js`의 직접 등록 공연은 0건입니다. 기존 구조를 삭제하지 않았습니다. 직접 등록한 참고 공연이 향후 추가돼도 KOPIS ID가 없으면 주요 검색 결과에 섞지 않습니다. 같은 KOPIS ID가 있는 경우 검증된 보조 링크만 결합하고 KOPIS 상세정보나 자동 프로그램 매칭을 수동 정보로 덮어쓰지 않습니다.

## 조회와 판정

1. 지역 코드, 시작일·종료일, `shcate=CCCA`, 공연 상태 `prfstate=01/02`를 실제 목록 요청에 적용합니다. 예정·진행 상태를 각각 페이지 끝까지 조회하고 KOPIS ID로 중복 제거합니다. 대상 곡 ID는 프로그램 비교에 사용하며 공연 제목 검색어로 바꾸지 않습니다.
2. 상세·OCR 확인 요청에도 같은 지역·기간 `query`를 전달합니다. 목록에 없는 ID는 상세 조회하지 않습니다. 상세의 지역·기간·장르·공연 상태가 바뀌었으면 OCR 전에 제외합니다. 오래된 상세 캐시가 조건과 충돌하면 상세를 새로 조회합니다.
3. 기본정보는 KOPIS 상세가 기준입니다. `PROGRAM`, 프로그램, 연주 곡목, 1부·2부 등 명시된 구역을 먼저 분석합니다. 홍보문·프로필·경력·음반 소개 등 단순 언급은 자동 매칭하지 않습니다.
4. 작곡가·작품 유형·Op./작품목록 번호·곡 번호·검증된 별칭·알려진 조성·악장·발췌 범위를 비교합니다. 작곡가나 작품번호 충돌, 혼합 표기, 편곡 및 연주 범위 불명확은 확정하지 않습니다. 작품 단위 안내는 선택 악장의 연주 확정과 구분합니다.
5. 텍스트로 판정할 수 없는 KOPIS 소개 이미지에만 Tesseract.js OCR을 적용합니다. 앞의 이미지가 포스터나 소개일 수 있으므로 제한 안에서 뒤쪽 이미지도 확인합니다. 공연 ID·상세에 선언된 이미지 URL·공연명/출연자·날짜·장소·시리즈·프로그램 문맥과 식별 단어의 품질을 함께 확인합니다. OCR 신뢰도 한 값만으로 일치시키지 않습니다.
6. 일부 이미지가 미처리되거나 문맥이 불명확하면 확정 불일치로 바꾸지 않습니다. 공연별 실패는 다른 후보 확인을 막지 않습니다. 중단·조건 변경 이후 늦은 응답을 버리고 새 OCR 작업을 추가하지 않습니다.

상태·장르 코드 출처: [KOPIS OpenAPI 공통코드](https://www.kopis.or.kr/upload/openApi/%EA%B3%B5%EC%97%B0%EC%98%88%EC%88%A0%ED%86%B5%ED%95%A9%EC%A0%84%EC%82%B0%EB%A7%9DOpenAPI%EA%B3%B5%ED%86%B5%EC%BD%94%EB%93%9C.pdf).

## 상태와 화면

각 KOPIS ID는 한 시점에 하나의 대표 상태를 가집니다.

| 내부 상태 | 의미 | 화면 |
| --- | --- | --- |
| `matched` | 작품 포함 확인 | 확인된 공연 |
| `pending` | 상세정보 조회 대기 | 아직 확인하지 않은 후보 |
| `processing` | 프로그램 분석 중 | 아직 확인하지 않은 후보 |
| `image-required` | 이미지 OCR 필요 | 아직 확인하지 않은 후보 |
| `needs-review` | 자료·작품·범위 추가 확인 필요 | 확인이 더 필요한 공연 |
| `no-material` | 프로그램 자료 없음 | 확인이 더 필요한 공연 |
| `failed` | 분석 실패 | 확인이 더 필요한 공연 |
| `not-found` | 확인 범위 내 작품 불일치 | 별도 집계 안내 |

KOPIS 후보 수, 조회 시도 수, 처리 완료 수와 8개 대표 상태를 따로 표시합니다. 실패나 미확인 후보가 남아 있으면 전체 확인 완료를 표시하지 않습니다. 일치 결과가 먼저 나오더라도 처리가 계속되면 **일치 공연 N개 발견 · 다른 후보 확인 중**을 표시합니다.

확인된 카드에는 공연명·KOPIS ID·기간·공연장·공연 상태·출연진·연결 작곡가/작품·작품번호/곡 번호·연주 범위·짧은 근거·텍스트/OCR 근거 유형·KOPIS 상세 링크를 표시합니다. 검증된 보조 공식 링크가 있으면 함께 표시하며 링크를 추측해서 생성하지 않습니다. 공식 공연장 링크는 KOPIS 응답에 실제로 있는 예술의전당·롯데콘서트홀 링크 또는 동일 KOPIS ID의 검증된 직접 등록 보조 정보에서만 가져옵니다.

## 캐시와 OCR 운영

- 목록·상세·분석은 기본 6시간 캐시를 사용합니다. 프로그램 이미지 결과는 KOPIS ID + 이미지 URL로 연결하고 재다운로드한 콘텐츠 해시가 바뀌면 다시 읽습니다.
- 원문·추출 결과·상태·처리 시각·출처는 서버의 `.cache/` 또는 Vercel 임시 공간에 저장합니다. 다른 곡 검색에서도 동일 OCR 결과를 재사용하고 작품 비교만 다시 합니다.
- 캐시 일치 결과를 먼저 표시한 뒤 나머지 후보 확인을 계속합니다. 처음/추가 확인은 각각 최대 10개, 기본 요청 묶음은 2개, OCR worker는 프로세스당 1개입니다.
- 기존 다운로드 크기·화소·시간·대기열 제한을 유지합니다. 분석 기준 변경에 맞춰 OCR/공연 분석 캐시 버전은 `program-ocr-4`, 브라우저 목록 캐시는 `classic-atlas-concert-cache-v2`로 바꿨습니다.
- Vercel의 인스턴스별 임시 캐시는 영구 저장이나 인스턴스 간 공유를 보장하지 않습니다. 긴 OCR 요청은 함수 실행 한도에 걸릴 수 있습니다. 운영 설정은 [KOPIS 설정](KOPIS_SETUP.md), [OCR 운영 안내](PROGRAM_OCR.md)를 참고하세요.

## 2026-10-14 검증 결과

### 자동 테스트와 빌드

전체 자동 테스트 **92개**와 프로덕션 빌드가 통과했습니다. 지역·기간·장르·예정/진행 상태의 실제 요청 파라미터, 목록 밖 ID 상세 차단, 상세 조건 충돌 시 OCR 차단, 중복 제거, 프로그램 텍스트 우선 처리, 작곡가/작품번호/조성 충돌, 다른 날짜/시리즈/이미지 출처, 프로필/경력, OCR 23/28 불일치, 악장/전곡 구분, 일부 이미지 처리, 다른 곡 캐시, 취소/늦은 응답, 상태 합계와 카드 렌더링을 확인했습니다.

빌드 산출물 14개를 검사해 실제 서비스키가 포함되지 않았음을 확인했고, 환경 파일·OCR 캐시·언어 모델·검증 원문 파일이 공개 빌드에 포함되지 않았습니다. 서비스키 값은 출력하지 않았습니다.

### 실제 KOPIS API

한국 시간 2026-10-14 오전, 서울 **2026-10-14~31** 클래식 예정·진행 공연을 새로 조회했습니다.

- 고유 KOPIS 후보 **225건**, PF302595 포함.
- 예술의전당 **61건**, 롯데콘서트홀 **20건**이 일반 KOPIS 후보에 포함됐습니다. 공연장 이름을 검색 조건이나 후보 생성 규칙에 하드코딩하지 않았습니다.
- 각 공연장에서 실제 후보 1건씩 상세를 확인했습니다. 예술의전당 PF303231은 소개 텍스트 781자·이미지 1장, 롯데콘서트홀 PF302993은 소개 텍스트 2,868자·이미지 1장이 해당 KOPIS 상세에 연결되어 있었습니다. 이는 두 공연의 쇼팽 발라드 1번 포함 확인이 아니라 등록·상세·자료 연결 검증입니다.
- 실제 HTTP 검색/확인 경로로 대상 곡 ID와 지역·기간을 전달했습니다. 목록 요청에는 `stdate=20261014`, `eddate=20261031`, `signgucode=11`, `shcate=CCCA`, `prfstate=01/02`가 적용됐습니다.

### 실제 OCR: 새 분석과 캐시 재사용 구분

PF302595는 기존 공연 분석 결과가 없는 새 캐시 디렉터리에서 상세·소개 이미지 **3장**을 다시 조회하고 OCR했습니다. 언어 모델 파일만 재사용했습니다. 포스터의 공연 정보, 연주자 소개, 뒤쪽 프로그램 이미지를 구분했고 프로그램 구역에서 `F. Schubert / Two Impromptus, Op.90 / No.3 in G flat major / No.2 in E flat major`와 `F. Chopin / Ballade No.1 in G minor / Op.23`을 확인했습니다. 작품집 제목 다음 줄의 개별 곡번호를 각각 분리하고, D.899가 생략돼도 Op.90·곡번호·조성이 일치하면 슈베르트 즉흥곡 2번과 3번에 연결합니다. 세 곡 모두 **작품 포함 확인**, 근거 유형은 **KOPIS 소개 이미지 OCR**입니다.

이후 같은 작품과 다른 작품으로 캐시를 재사용했을 때 추가 KOPIS 요청과 추가 이미지 다운로드는 각각 **0회**였습니다. 같은 캐시를 사용하는 새 서비스 객체에서도 작품 포함 상태가 유지됐습니다. 최신 코드로 실제 캐시를 다시 판정하고 공연 상세 화면을 열지 않은 검색 컴포넌트에 렌더링하여 카드 **1개**, KOPIS ID·상세 링크·OCR 근거 유형을 확인했습니다. 이 렌더링 검증은 저장된 실제 OCR 결과를 사용한 것이며 새 OCR 검증과 구분합니다.

PF300769도 실제 상세와 이미지 **4장**을 새로 확인했습니다. 공연명과 이미지의 시리즈 표기 충돌이 감지되어 **추가 확인 필요**로 유지됐고 주요 결과로 확정하지 않았습니다. 앱의 동작에 이 공연 ID를 예외로 하드코딩하지 않았습니다.

### 아직 검증하지 못한 내용과 누락 가능성

- 연결된 브라우저가 없어서 실제 모바일 화면과 브라우저 클릭 흐름을 검증하지 못했습니다. React DOM 이벤트/상태/카드/링크는 자동 테스트했고, 좁은 폭의 상태 그리드·줄바꿈·버튼 크기는 CSS를 확인했습니다. 실제 화면 검증과 동일한 것으로 보고하지 않습니다.
- 실제 Vercel 배포의 OCR worker·모델 다운로드·함수 실행시간·인스턴스 간 캐시 동작은 별도 배포 후 확인이 필요합니다. 이번 검증은 로컬 Node 서버입니다.
- 225건 전체의 프로그램을 모두 OCR한 것은 아닙니다. 모든 국내 공연의 수집·누락 없음도 보장하지 않습니다.
- KOPIS 미등록 공연, 소개 자료 없음, 프로그램 구역 불명확, 낮은 이미지 품질, 다른 회차/시리즈, 작품번호 누락, 처리 한도와 부분 자료 때문에 실제 연주 공연이 검색 결과에 나타나지 않을 수 있습니다. 정확성을 우선해 근거가 부족한 공연은 확정하지 않습니다.

## 사용자가 확인할 순서

1. `npm run dev` 또는 `npm run build` 후 `npm start`로 앱을 실행합니다. Vercel은 새 코드를 배포하고 서버 환경변수 `KOPIS_SERVICE_KEY`를 등록합니다.
2. 보관함의 쇼팽 발라드 No.1 Op.23에서 **이 곡의 공연 찾기**를 누르거나 공연 찾기에서 해당 곡을 선택합니다.
