1. ‘음악 이야기’ 화면 단순화

현재 하단의 ‘음악 이야기’를 선택했을 때 화면 제목이
‘내 음악 기록’으로 표시되는 부분을 다음처럼 변경한다.

- 영문 보조 제목: MUSIC STORIES
- 화면 제목: 음악 이야기
- 설명 문구는 기존 서비스 분위기에 맞게 유지하거나
  ‘음악으로 나눈 이야기를 만나보세요.’로 변경한다.

‘음악 이야기’ 화면에서는 공개 피드 기능만 노출한다.

현재 상단의 다음 탭과 버튼을 모두 제거한다.

- 피드
- 개인 원본
- 내 프로필
- 로그아웃·계정 전환

피드만 남더라도 ‘피드’라는 별도 탭이나 제목은 표시하지 않는다.
화면 제목 ‘음악 이야기’ 아래에서 게시물 목록이 바로 시작되게 한다.

유지해야 하는 기능:

- 전체 피드
- 곡별 피드
- 사용자별 게시물
- 개별 게시물 딥링크
- 좋아요
- 댓글
- 팔로우
- 차단
- 신고
- 공유 범위에 따른 조회 권한
- Realtime 갱신·재연결
- 작성자·곡 선택 링크
- 기존 #music/post, #music/profile, #music/track 딥링크 호환

다른 사용자의 프로필과 게시물 확인 기능은 피드 탐색 기능이므로 유지한다.
단, 로그인 사용자가 자신의 프로필을 선택하면 통합된 ‘내 프로필’ 화면으로 이동한다.

기존 피드의 ‘기록 작성’ 버튼은 통합 ‘내 프로필’ 화면의
‘내 기록’ 섹션으로 이동하게 한다.

로그인했지만 공개 프로필이 없는 경우 피드 안에서 ProfileEditor를 직접 표시하지 않는다.
대신 다음 안내와 이동 버튼을 표시한다.

- 안내: 음악 이야기에 참여하려면 내 프로필을 먼저 만들어주세요.
- 버튼: 내 프로필 만들기

2. ‘나의 취향’을 ‘내 프로필’로 변경

기존 activeView='taste'의 내부 식별자는 호환성을 위해 유지해도 되지만,
사용자에게 표시되는 명칭은 모두 ‘내 프로필’로 변경한다.

변경 대상:

- 화면 제목 ‘나의 취향’ → ‘내 프로필’
- 영문 보조 제목 ‘MY TASTE’ → ‘MY PROFILE’
- 접근성 이름
- 관련 로그인 안내 문구
- 빈 화면 안내
- 버튼 및 내부 링크
- 테스트의 사용자 표시 문구

기존 ‘나의 취향’ 기능은 삭제하지 않고 통합 프로필의
‘나의 음악 취향’ 섹션으로 이동한다.

유지 항목:

- 보관한 곡 수
- 감정 성향 지수
- 대표 감정
- 전체 감정 그래프
- 내 취향 추천 보기
- 로그인 전 로컬 보관함 기반 취향
- 로그인 후 계정 동기화된 취향

3. 통합 ‘내 프로필’ 화면

내 프로필 화면은 다음 순서의 섹션으로 구성한다.

A. 공개 프로필

- 프로필 이미지
- 공개 닉네임
- @아이디
- 팔로워 수
- 팔로잉 수
- 공개 프로필 만들기·수정
- 다른 사용자에게 보이는 내 프로필 확인
- 내가 공유한 게시물 보기

현재 MusicSocial에 있는 ProfileEditor와
‘내 게시물·팔로워 보기’ 기능을 이곳으로 이동한다.

B. 내 기록

현재 ‘개인 원본’ 및 MyMusicRecords 기능을 이곳으로 이동한다.

표시 명칭은 ‘개인 원본’이 아니라 ‘내 기록’으로 통일한다.

유지 기능:

- 전체 개인 기록 조회
- 기록 작성·수정·삭제
- 보관을 해제한 곡의 기록 유지
- 공유하기
- 공개 범위 변경
- 공유 취소
- 개인 기록 삭제 시 공유본 연계 삭제
- 페이지 추가 로딩

기록에는 원본이라는 용어 대신 사용자에게 이해하기 쉬운 상태를 표시한다.

- 나만 보기
- 팔로워 공개
- 전체 공개
- 공유 중

가능하면 다음 필터를 제공한다.

- 전체
- 나만 보기
- 공유 중

DB의 원본·공유본 분리 구조와 권한 정책은 변경하지 않는다.

C. 나의 음악 취향

기존 PreferenceScreen의 취향 그래프와 추천 이동 기능을 배치한다.

D. 활동 관리

- 차단한 사용자 목록
- 차단 해제
- 내가 공유한 게시물 확인
- 개인정보 처리 안내

E. 계정

기존 AccountPanel 기능을 통합한다.

- Google 계정 이름과 이메일
- 보관함 동기화 상태
- 다른 Google 계정으로 전환
- 로그아웃
- 계정과 데이터 삭제

‘다른 Google 계정으로 전환’과 ‘로그아웃’을 별도 버튼으로 구분한다.

계정 전환은 현재 useGoogleAuth 구현을 먼저 확인하고,
기존 계정의 로컬 사본 정리 → 로그아웃 → Google 계정 선택 화면 순서가
안전하게 동작하도록 구현한다.

가능하면 Google OAuth의 계정 선택 옵션을 사용하되
기존 PKCE·세션·redirect 흐름을 깨뜨리지 않는다.

계정과 데이터 삭제는 가장 아래의 별도 위험 영역에 두고
기존 2단계 확인과 연계 삭제 정책을 유지한다.

4. 보관함의 중복 제거

현재 보관함 안에 있는 다음 보기 전환을 제거한다.

- 보관한 곡
- 내 음악 기록

보관함 화면은 다시 찾아 듣고 싶은 ‘보관한 곡’만 보여준다.
전체 음악 기록 목록은 통합 ‘내 프로필 > 내 기록’에서만 제공한다.

단, 각 곡의 상세 화면에 있는 ‘나의 음악 기록’ 작성 기능은
곡을 보면서 바로 기록하는 문맥 기능이므로 그대로 유지한다.

5. MusicSocial 책임 분리

MusicSocial은 피드와 공개 소셜 탐색만 담당하도록 정리한다.

MusicSocial에서 제거·이동할 기능:

- records 탭
- profile 탭
- Account 관련 버튼
- MyMusicRecords 렌더링
- 자신의 ProfileEditor 직접 렌더링
- 차단 관리 화면
- 로그아웃·계정 전환 버튼

내 프로필 화면에는 필요한 개인 프로필 API만 연결한다.
프로필 화면을 열었다고 전체 피드 Realtime 구독이 중복 생성되지 않게 한다.

공통 API와 컴포넌트는 재사용하되 피드와 프로필 사이에서
동일한 요청·구독·상태가 중복 실행되지 않도록 구조를 정리한다.

6. 하단 내비게이션 아이콘 전용 변경

현재 하단 메뉴의 다음 텍스트를 화면에서 모두 제거한다.

- 음악 탐색
- 공연 찾기
- 보관함
- 나의 취향
- 음악 이야기

아이콘 5개만 표시한다.

아이콘 의미:

- 나침반: 음악 탐색
- 무대: 공연 찾기
- 북마크: 보관함
- 사용자: 내 프로필
- 피아노: 음악 이야기

요구사항:

- 아이콘 시각 크기: 28px 권장
- 버튼 터치 영역: 최소 48×48px
- 다섯 버튼을 동일한 너비로 배치
- 아이콘이 세로·가로 중앙에 정렬
- iPhone safe-area 하단 여백 반영
- 콘텐츠가 하단 내비게이션에 가려지지 않게 padding 확보
- 활성 메뉴는 색상만이 아니라 배경·원형 또는 pill 형태로 명확히 구분
- 활성 버튼에 aria-current='page' 적용
- 모든 버튼에 aria-label과 title 제공
- 텍스트를 단순히 삭제해 접근 가능한 이름이 없어지지 않게 할 것
- 필요하면 화면에는 보이지 않는 sr-only 텍스트 사용
- 아이콘 SVG는 aria-hidden=true 유지
- 320/375/390/520px에서 잘림·겹침·가로 스크롤이 없어야 함

7. URL과 이동 호환성

기존 링크와 브라우저 뒤로가기를 유지한다.

- #music
- #music/post/{id}
- #music/profile/{id}
- #music/track/{id}

자신의 프로필 링크는 통합 내 프로필 화면으로 연결한다.
다른 사용자의 프로필 링크는 음악 이야기 안의 공개 프로필 화면으로 유지한다.

피드에서 내 기록으로 이동할 때 내 프로필 화면의 ‘내 기록’ 섹션으로
스크롤하고 제목에 focus를 이동해 접근성을 유지한다.

8. UI·타이포그래피

전체 서비스 공통 규칙을 유지한다.

- Pretendard
- letter-spacing: -0.03em
- 최소 12px
- 짝수 글자 크기만 사용
- 한 줄 line-height: normal
- 실제 2줄 이상 텍스트 line-height: 1.5
- 버튼 터치 영역 최소 44px, 하단 메뉴는 48px
- 모바일 줄바꿈·텍스트 잘림·키보드 focus 확인

통합 프로필은 긴 단일 페이지가 되므로 각 영역을 카드 또는 명확한 section으로 구분한다.
계정 삭제를 제외한 핵심 기능을 과도한 accordion 안에 숨기지 않는다.
