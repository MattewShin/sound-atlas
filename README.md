# Classic Atlas

듣고 싶은 한글 감정 키워드나 현재 기분으로 피아노 음악을 탐색하고, 마음에 남는 곡을 보관하는 React 19 + Vite 6 앱입니다.

활성 목록은 총 77곡입니다. 쇼팽 36곡(Op.10·Op.25 연습곡 각 12곡, 소나타 No.2 Op.35·No.3 Op.58의 각 4악장, 발라드 4곡), 라흐마니노프 4곡, 사티 짐노페디 3곡, 리스트 사랑의 꿈 1곡, 베토벤 21악장에 차이콥스키 《사계》 Op.37a의 1~12월 12곡을 더했습니다. 《사계》는 월별 곡이 독립적인 추천·보관 단위이며, 제공된 한글·영문 제목과 아홉 감정 점수·감상 설명·월별 영상 구간을 연결했습니다.

## 실행과 검증

```sh
npm install
npm run dev
npm test
npm run build
npm run diagnose:recommendations
```

`npm test`는 확정 CSV의 693개 점수 대조, 추천 순위·동점·미평가, 취향 프로필·코사인 유사도, 36곡·44곡·65곡 버전의 저장 상태 보존, 영상 등록 구간 재사용, 추천 카드 8개 제한·전체 목록 20곡 단위 표시·순위 유지·중복 방지·마지막 페이지, 실제 JSX 컴파일과 서버 렌더링을 확인합니다. 서버 렌더링은 실브라우저의 모바일 잘림·클릭 검증을 대신하지 않습니다.

## 감정과 추천

감정의 순서·내부 키·한글 운영 명칭은 `src/data/emotions.js`가 단일 기준입니다. 화면에서 감동적인, 압도적인, 몽환적인, 부드러운, 평안한, 경쾌한, 힘찬, 긴장감 있는, 애잔한을 고릅니다. 느낌 선택은 최대 3개이며 동일 가중치입니다. 기분 선택은 `src/data/feelingSuggestions.js`의 별도 제품 정책으로 즉시 감정 키에 연결합니다. 추가 키워드·강도 선택 단계는 없습니다.

원점수 1~5를 `(s - 1) / 4`로 정규화합니다. 선택 감정의 평균 점수로 정렬하며, 선택 감정 중 하나 이상이 3 이상인 곡만 추천합니다. 후보가 부족하면 결과 개수를 줄입니다. 전체 후보 목록의 동점은 3 이상인 선택 감정 개수, 활성 개인화 유사도, 안정적인 ID 순서로 해소합니다. 기본 키워드 화면의 대표곡은 최고 평균 점수의 동점 후보 전체에서 무작위로 한 곡을 선택합니다. 키워드·기분을 선택할 때 다시 추첨하고 보관·해제·상세 조회 같은 일반 화면 갱신에는 대표곡을 유지합니다. 새로고침하면 다시 추첨합니다. 단독 최고점 곡이 있으면 그 곡을 유지하며 더 낮은 점수는 추첨하지 않습니다. 기본 키워드 화면은 개인화하지 않으며 내 취향 추천은 별도 전환으로 제공합니다.

## 보관함과 나의 취향

메인 화면은 대표곡 1개와 대표곡을 제외한 추천 순위 상위 최대 8곡을 가로 카드로 표시합니다. ‘추천곡 더 보기’는 대표곡을 포함한 전체 추천 목록으로 이동합니다. 전체 목록은 같은 추천 순서로 처음 20곡을 표시하고 ‘더 불러오기’로 다음 20곡씩 추가합니다. 이미 표시된 곡은 중복되지 않으며 마지막에는 불러오기 버튼을 숨깁니다. 키워드·기분·추천 방식이 바뀌거나 내 취향의 보관 기준이 바뀌면 표시 개수는 20곡부터 다시 시작합니다. 전체 목록에서 곡 상세·영상·보관 기능을 사용할 수 있으며 목록을 열거나 추가로 불러오는 동작은 대표곡을 다시 추첨하지 않습니다.

실제로 보관한 활성·평가 완료 곡만 중복 없이 사용합니다. 감정별 정규화 평균의 9차원 벡터가 취향 프로필입니다. 보관곡 1개부터 0이 아닌 프로필이 활성화되고, 3곡 미만이면 초기 취향으로 안내합니다. 감정 성향 지수는 프로필×100이며 차트는 0~100 고정 축입니다. 비율이나 확률이 아니며 합계가 100일 필요가 없습니다. 상위 감정 동점은 공동으로 표시합니다. 빈 보관함과 0벡터는 미형성 상태이며 차트·취향 추천을 만들지 않습니다.

내 취향 추천은 같은 9차원 벡터의 코사인 유사도로 정렬하고 이미 보관한 곡을 제외합니다. 모두 보관하면 빈 결과를 안내합니다. 키워드 추천으로 돌아갈 수 있으며 보관·해제 때와 새로고침 때 새 점수로 프로필을 계산합니다. 추천이나 상세 조회는 취향의 입력이 아닙니다. 취향 화면에는 현재 활성 목록의 곡 수와 작곡가를 안내합니다.

## 데이터 관리

공연 찾기는 보관함·곡 상세에서 곡을 고르거나 화면에서 기존 곡 DB를 검색해 곡을 선택한 뒤, 지역·관람 기간을 설정해 KOPIS의 클래식 공연 목록을 조회합니다. 곡을 선택하기 전에는 목록·상세·OCR 요청을 보내지 않습니다. 같은 지역·기간은 초기 6시간 캐시를 재사용하고 ‘최신 정보로 새로고침’은 API를 다시 호출합니다. 곡을 바꿔도 기존 OCR 캐시는 작품 비교에 재사용하지만 새 곡의 검색은 버튼을 눌러야 시작합니다. 설정·운영 서버·배포 방식은 [KOPIS 설정 안내](docs/KOPIS_SETUP.md)에 정리했습니다. 자동 수집이나 예약 실행은 없습니다.

현재 직접 등록된 공연은 없습니다. 공연 찾기 화면은 선택한 곡의 작품 포함이 확인된 공연을 주 결과로 표시합니다. 음악 탐색의 감정 추천과 보관함 기반 곡 추천은 유지하되 감정 키워드는 공연 검색 조건으로 사용하지 않습니다.

- `src/data/concerts.js`: 직접 등록한 공연 목록은 비어 있으며, 작품 식별에는 기존 곡 데이터에서 파생한 정보를 사용합니다. 기존 곡 ID와 보관 기록은 그대로 사용합니다.
- `src/data/concertRecommendations.js`: 프로그램과 곡 평가의 기존 분석 함수는 유지합니다. 현재 공연 검색 화면은 감정·보관함 분석 점수 대신 선택한 곡의 작품 포함 근거를 보여줍니다. 음악 추천의 감정 점수와 보관함 추천은 계속 사용합니다.
- `src/data/concertTrackSearch.js`: 기존 곡 ID를 대상으로 한 곡명·작곡가·별칭·작품번호 검색. 검색 문자열 자체를 공연 프로그램이나 OCR 원문과 비교하지 않고 선택된 ID의 작품 정보를 서버에 전달합니다.
- `src/components/ConcertScreens.jsx`: 공연 카드·상세·확보한 프로그램·악장별 실제 점수·곡 상세·기존 미리듣기 연결. 작품 안내를 특정 악장 연주 확정으로 해석하지 않습니다.
- 한국 시간 티켓 오픈 전에는 ‘예매 오픈 예정’, 이후에는 공식 페이지 확인 안내를 표시합니다. 정확한 시작 시각을 아는 등록 공연은 시작 후 예정 목록에서 제외합니다. KOPIS의 기간 정보만 있는 공연은 회차 시간을 추정하지 않고 완료 상태·기간 종료를 기준으로 제외합니다. 좌석·판매 가능 상태를 추정하지 않습니다.
- KOPIS 검색은 기본 정보와 프로그램 확보를 분리합니다. 보관함의 ‘이 곡의 공연 찾기’는 실제 곡 ID를 서버로 전달합니다. 첫 검색에서 최대 10개 후보를 2개씩 점진적으로 확인하고, ‘더 찾아보기’ 한 번으로 다음 최대 10개를 확인합니다. 텍스트를 먼저 읽고 필요한 경우 소개 이미지 전체에 무료 Tesseract.js OCR을 적용합니다. 공연명·날짜·장소와 이미지의 관계, 프로그램 문맥, 작곡가·작품번호·곡번호·연주 범위를 검증한 일치 공연만 주 결과에 표시합니다. 후보별 대표 상태 7개와 조회 시도·처리 완료를 별도로 집계하며, 불완전한 자료는 불일치로 확정하지 않습니다. 이미지별 OCR 원문과 작품 추출 결과는 공연·이미지 URL·콘텐츠 해시를 기준으로 재사용합니다. 자세한 설정과 한계는 [프로그램 OCR 안내](docs/PROGRAM_OCR.md)를 참고하세요.

`npm test`는 곡·보관함·공연 추천과 검색 캐시·오류·페이지 처리, 프로그램 경계·작품번호, OCR 문맥·숫자 판독·부분 자료, 취소·중복 실행·상태 집계와 React DOM 흐름을 확인합니다. 실제 KOPIS의 PF302595에서는 이미지의 `F. Chopin / Ballade No. 1in G minor, Op. 23`을 OCR 원문에서 읽어 기존 `chopin-ballade-op23-no1`과 연결했습니다. 다른 곡으로 다시 비교할 때 이미지 OCR을 반복하지 않았고, PF300769의 시리즈 표기 충돌은 계속 확인 필요 상태로 유지했습니다. 실제 데이터와 자동 테스트의 범위는 [OCR 검증 기록](docs/PROGRAM_OCR.md)에 구분했습니다. 실브라우저 모바일 시각 검사는 아직 완료하지 못했습니다.

- `src/data/manualRatings.js`, `src/data/tchaikovskySeasons.js`: 확정 수동 평가 77곡·693개 점수. `ratingSource: manual`, `ratingVersion: manual-emotions-1`. 사계 12곡의 영문 표기는 작품 검색·프로그램 매칭에도 사용합니다.
- `data/manual/manual-emotions-v1.csv`: 사용자가 제공한 확정 입력 대조본. 작곡가 확장에 맞춰 기존 `chopin-emotions-v1.csv`를 이름 변경했습니다.
- `data/manual/catalog-update-2026-10-13.json`: 사용자 제공 기존 62곡의 최신 입력 대조본. 558개 점수·영문/한글 제목·요약·작품 배경과 감상 포인트·유튜브 링크·재생 구간·출처를 보존합니다. 전체 목록의 ID와 순서를 유지하고, 점수와 요약은 `manualRatings.js`, 상세 설명과 영상은 `manualTrackDetails.js`에 반영했습니다.
- `src/data/musicData.js`: 활성 목록·공용 이미지 맵·상세·구 ID 매핑. 별칭은 별도 데이터로 관리하고, 화면에서는 곡명 뒤에 공백 한 칸을 두고 `[비창]`처럼 대괄호로 감싸 강제 줄바꿈 없이 같은 서식으로 표시합니다.
- `src/data/recommendations.js`: 점수 추천·취향 프로필·코사인 유사도.
- `src/data/storage.js`: 음악 저장 상태만 버전별 정리.
- `data/emma/`: 앱과 분리된 과거 EMMA 검증 참고 자료. 원본 CSV는 사용자 요청으로 삭제했으며, `archive/`는 교체 전 매칭·검토 기록입니다.
- `data/manual/legacy-media.json`: 이전 영상 등록 참고본. 앱은 직접 읽지 않으며, 월광 세 악장은 최신 사용자 제공 바렌보임 영상으로 갱신했습니다.
- [평가 지침](data/manual/rating-guide.md): 점수 정의와 신규 곡 등록 방법.

대표 키워드는 3 이상인 감정 중 점수 상위 최대 3개이며 동점은 기준표 순서입니다. 전체 감정 점수는 상세에서 표시합니다. 미평가는 null로 두고 검토 대상으로 표시하며 추천과 취향 집계에서 제외합니다. EMMA 가져오기 도구는 참고 자료만 갱신하며 수동 평가를 변경하거나 곡을 자동 매칭하지 않습니다.

작곡가 이미지는 `composerImages`에서 공용 파일을 카드·상세·보관함에 공유합니다. 새 차이콥스키 초상은 [Wikimedia Commons의 CC0 이미지](https://commons.wikimedia.org/wiki/File:Portret_van_Pyotr_Ilyich_Tchaikovsky,_RP-F-F00667-AE.jpg)를 800×600 카드로 가공했습니다. 영상은 정확히 같은 작품·곡번호·악장에만 연결합니다. 현재 77곡 모두 제공된 유튜브 영상·재생 구간을 사용합니다. 기존 62곡의 최신 영상·연주자·채널·종료 시각은 사용자 입력 그대로 반영했으며, 외부 메타데이터나 실제 청취로 별도 검증하지 않았습니다.

## 로컬 저장 마이그레이션

`classic-atlas-track-reactions-v1`의 `listenAgain` 보관 상태와 `liked` 기록을 사용합니다. 데이터 버전 `manual-catalog-5`는 `classic-atlas-music-data-version`에 저장합니다. 기존 36곡·44곡·65곡 버전의 ID와 보관·좋아요는 유지합니다. 키워드 선택은 현재 화면에서만 유지하고 새로고침하면 초기화합니다. 이전 `classic-atlas-music-selection-v1` 저장값은 앱 시작 시 제거합니다. 더 오래된 구 ID는 정확한 두 쇼팽 악장과 라흐마니노프 Op.23 No.5, 사티 짐노페디 No.1, 리스트 사랑의 꿈 No.3, 베토벤 월광 1·3악장·발트슈타인 1악장·열정 3악장을 명시적으로 연결합니다. 구 라흐마니노프 Op.3의 잘못된 곡번호는 추정 매칭하지 않습니다. 이미 삭제된 보관 기록을 복구하지는 않습니다. 다른 구 곡 참조는 제거하며 인증·다른 설정은 보존합니다.

선택값은 `classic-atlas-music-selection-v1`에 감정 키로 저장합니다. 유효한 키·현재 한글명은 유지하고 이전 편안한만 평안한으로 변환합니다. 따뜻한·장엄한 등으로 새 평가를 추정하지 않습니다. 최근 곡 키 `classic-atlas-recent-tracks-v1`이 있으면 ID 매핑·중복 제거를 적용합니다. 과거 취향·강도·추천 캐시 키만 폐기합니다. 정리된 보관곡이 있으면 한 번 안내하며 동일 버전 재실행은 추가 삭제를 하지 않습니다. `localStorage.clear()`는 사용하지 않습니다.

로그인·서버 DB·외부 음원 API·실제 공연 예매는 현재 범위에 포함되어 있지 않습니다. KOPIS 검색은 서버 전용 서비스키와 Node API를 사용합니다. `.env.example`을 참고하고 개발은 `npm run dev`, Node 운영은 `npm run build` 후 `npm start`로 실행합니다. Vercel에서는 `api/index.js`와 `vercel.json`이 공연 API를 연결합니다. Vercel 환경변수에 `KOPIS_SERVICE_KEY`를 등록하고 이 코드가 포함된 새 배포를 실행하세요. 단계별 확인 방법은 [Vercel 배포 안내](docs/KOPIS_SETUP.md#vercel-배포)에 있습니다.

지역 선택은 공연 찾기에서 곡을 선택한 뒤 검색 조건 안에 표시합니다. 화면 폭에 맞는 선택 창에 전국·시도 목록을 3열 버튼으로 배치하며, 선택하면 창이 닫힙니다. 닫기 버튼·바깥 영역·Escape 키로도 닫을 수 있습니다. 기본값은 서울이며 선택은 `classic-atlas-concert-region-v1`에 별도로 저장해 탭 이동과 새로고침 후에도 유지합니다. 선택한 지역·기간은 검색 버튼을 누를 때만 조회 조건으로 적용합니다.
